# v0.1.1 Stabilization Implementation Plan

> **For agentic workers:** REQUIRED SUB-SKILL: Use superpowers:subagent-driven-development (recommended) or superpowers:executing-plans to implement this plan task-by-task. Steps use checkbox (`- [ ]`) syntax for tracking.

**Goal:** Ship a tested corrective release for the two plugins and devkit, then merge and push it to GitHub.

**Architecture:** Preserve the existing zero-dependency ESM monorepo and pure-logic boundaries. Make targeted changes in the current Host/Client, search, extraction, and scaffold modules; do not introduce the future event store or change report schema version 1.

**Tech Stack:** Node.js >=22.15, `node:test`, browser React through the existing module loader, GitHub Actions, Markdown.

**Spec:** `docs/superpowers/specs/2026-10-26-v0.1.1-stabilization-design.md`

## Global Constraints

- Use ESM and Node.js >=22.15; add no runtime or development dependencies.
- Preserve `schemaVersion: 1` and existing report field meanings.
- Write regression tests before each behavior change and keep all pre-existing tests unless an assertion documents the defective behavior being corrected.
- Do not read personal `~/.dsh` data in the default test command.
- Do not claim real GUI/DSH runtime verification unless it was actually performed.
- Do not modify or stage the pre-existing untracked `.progress.md` or `NEXT_STEPS.md`.
