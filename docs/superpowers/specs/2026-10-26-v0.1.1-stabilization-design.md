# v0.1.1 Stabilization Design

## Goal

Deliver a corrective release that fixes reproduced defects, removes misleading privacy and verification claims, strengthens devkit, and establishes a reproducible release baseline without starting the future event-level analytics or cross-host roadmap.

## Scope

This release includes:

- Preserve the Host-configured default usage window in the browser and prevent stale fetch responses from replacing newer results.
- Reject invalid negative `topN` configuration through a deterministic fallback and report CSV output sizes in bytes.
- Match DSH's whitespace-flexible literal search semantics when locating snippets, bound long-query snippets, preserve cancellation across asynchronous boundaries, and report the configured per-session cap accurately.
- Refresh changed extracted documentation/source, remove stale files within the extracted scope, and prevent packages absent from the current index from appearing in documentation search.
- Escape scaffold substitutions for JSON, JavaScript, and YAML, make the scaffold honor its own locale rules, and detect forbidden ESM as well as `require()` client imports.
- Keep real personal cache tests opt-in, add CI on the minimum and current major Node lines, add an MIT license, and update release documentation.
- Mark `session-search` as maintenance-only on DSH 0.2.1+ and direct users to the official workspace-authorized Session search bundle.

This release does not include:

- The future `UsageEvent` store, event-time accounting, per-model pricing, budgets, semantic memory, new standalone applications, or cross-host adapters.
- A claim that GUI installation or real DSH tool execution has been verified. Such verification remains explicitly listed as pending unless actually performed.
- A change to report `schemaVersion`; the existing report semantics remain frozen at version 1.

## Design

### Browser loading

The panel's initial window state is `null`. A null selection calls `/api/usage-insights` without a `window` query parameter, allowing the Host to apply `config.window`; the response's `window` drives the selected control. An explicit user selection always adds the query parameter.

Each load owns an `AbortController`. Starting another load aborts the previous request and only the current controller may update state. Effect cleanup aborts the active request. Abort errors are expected and do not replace the visible state with an error.

### Search correctness

`makeSnippet` reproduces the official literal matcher: trim, split on whitespace, escape regex metacharacters, join with `\s+`, and execute one Unicode-aware case-insensitive regular expression. Snippet offsets use the matched text rather than the query text, so flexible whitespace cannot displace the excerpt. A match longer than the content window returns at most `max` code points from the match, plus boundary ellipses.

Cancellation is checked after each non-cancellable `filterEvents()` call and before processing results. Abort errors from title lookup propagate; unrelated title failures still degrade to empty titles. `assembleResult` receives the effective per-session limit instead of reading a hard-coded constant, and its guidance says that `session_id` narrows the scan rather than promising unlimited results.

### Extraction and scaffolding

Extraction compares content before writing and reconciles generated files in the selected scope. Documentation search uses `INDEX.txt` as the package allowlist, so directories left by older installations cannot leak into current results. No broad cache deletion is performed.

Scaffold substitution becomes file-context aware: JSON and double-quoted YAML strings use JSON string escaping; JavaScript single-quoted strings escape backslashes, quotes, line terminators, and JavaScript line separators. The template patch uses double-quoted YAML strings. The template registers zh/en dictionaries, disposes registrations through `ctx.effect`, and passes its own checker with zero errors and zero warnings.

### Verification and release

Default tests never read `~/.dsh`; real-cache tests require `DSH_RUN_REAL_TESTS=1`. Their daily conservation assertion accounts for the report's 30-day cap. CI runs `npm test` and `npm run check` on Node 22.15 and 24 without installing runtime dependencies.

Documentation distinguishes local computation from model-provider transmission, identifies sensitive metadata, documents the official 0.2.1 search alternative, and avoids unverified compatibility or GUI claims. All existing package manifests move to version 0.1.1 and declare MIT; newly scaffolded user packages remain at version 0.1.0 and declare MIT by default.

## Acceptance

- New regression tests fail against the old behavior and pass after the fixes.
- `npm test` passes without reading personal caches.
- `npm run check` reports zero errors and zero warnings for both plugins and the generated template.
- `DSH_RUN_REAL_TESTS=1` remains available as an explicit local check and handles histories spanning more than 30 creation days correctly.
- The repository contains CI and an MIT LICENSE, package versions are 0.1.1, and changelog/security/readme statements match actual behavior.
- No changes are made to the pre-existing untracked `.progress.md` or `NEXT_STEPS.md` files.
